# Sub2 Smart Group

面向个人 sub2api 后台的 Tampermonkey 管理工具。它在不修改 sub2api 源码、前端文件或容器镜像的前提下，提供账号健康状态、真实路由记录、首字耗时、配置审计、优先级、日配额、手动余额查询、账号创建和分组感知模型管理能力。

从 `v2.0.0` 开始，项目已经移除全部 AIHub 页面匹配和业务代码，成为纯 sub2 专属工具。原有 `sub2-smart-group:` 存储键、GitHub Raw 更新地址和 userscript namespace 保持不变，升级后已有面板偏好不会因此丢失。

## 核心原则：不主动测活

上游禁止测活时，本脚本不会定时调用 test / probe，也不会为了判断健康状态发送模型请求。自动刷新只读取当前 sub2 后台的本机 Admin API：

- 账号健康和冷却状态；
- 分组与平台配置；
- 今日真实请求数和花费；
- 最近成功 / 失败请求、真实故障转移记录和已记录的流式请求首字耗时。

账号卡片中的“模型”按钮默认只读取 sub2 已保存的模型。只有用户明确点击“拉取并同步上游”时，才会通过 sub2 官方接口访问对应上游；返回模型会按账号真实分组平台过滤，再由用户确认后持久化。

添加账号也只从明确点击开始。脚本把当次输入的地址和 API Key 发送到当前 sub2 后台，由官方预览接口识别 OpenAI / GPT 或 Anthropic / Claude；确认后才调用官方创建接口，不从浏览器直接访问候选上游。

余额查询同样不会自动执行。只有用户明确点击“查余额”或“保存并查询”时，脚本才会把该账号单独配置的余额凭据发送到对应的白名单 HTTPS 上游。

## 安装与自动更新

1. 安装 Tampermonkey。
2. 打开以下 GitHub Raw 地址并安装：
   `https://raw.githubusercontent.com/hong594/sub2-smart-group/main/sub2-smart-group.user.js`
3. 登录 sub2api 后台，右下角会出现蓝色 `S2` 按钮。

脚本默认匹配：

```text
http://localhost:18080/*
http://127.0.0.1:18080/*
http://localhost:8080/*
http://127.0.0.1:8080/*
```

如果使用内网 IP、自定义域名或 HTTPS，请在 Tampermonkey 的本脚本设置中添加“用户匹配”，例如：

```text
http://192.168.x.x:18080/*
https://your-sub2-domain.com/*
```

脚本保留了 GitHub Raw `@updateURL` 和 `@downloadURL`。自动检查频率由 Tampermonkey 自身控制，也可手动执行“检查用户脚本更新”。

## 面板功能

### 账号状态与筛选

- 正常、注意、不可用、已停用四色健康总览；
- 按分组或全部账号展示；
- 按分组、平台和健康状态筛选；
- 按健康度、优先级、今日花费或名称排序；
- 搜索账号名称、平台和分组；
- 五个筛选项采用紧凑单行布局。

### 配置审计与互斥编辑器

- 余额、容量和日配额在整个列表中最多打开一个编辑器；再次点击当前编辑器会关闭，点击其它账号或类型会直接切换；
- 编辑器打开时仍可筛选、排序和切换视图；账号仍可见时保留草稿与焦点，被筛掉时清除未保存的敏感输入；
- 配置审计使用规范化后的分组名称、类别、严重级别和证据，不直接渲染后端原始分组对象；
- 容量建议独立展示，不计入审计问题数量。

### 最近命中与路由原因

- 最近一次成功请求实际使用的账号显示“最近命中”；
- 优先读取 `/admin/ops/requests`，运维接口不可用时才回退到 `last_used_at`；
- 展示真实的 401、403、429、502、503 等上游故障转移记录；
- 优先通过客户端请求 ID 关联失败账号和最终成功账号；
- 明确区分“已证实”“当前状态 / 配置判断”和“推测”；
- 对没有完整候选淘汰轨迹的情况，不会武断声称某账号一定没有被请求。

### 容量与路由诊断

- 读取 `/admin/ops/concurrency`，展示账号当前并发占用、最大容量、负载和排队数；
- 面板汇总按账号去重后的当前并发与总容量；
- 容量数据明确标记为当前快照，不冒充历史请求发生时的并发；
- “路由诊断”抽屉展示最近成功请求、实际失败账号和最终成功账号；
- 优先读取关联错误详情中的 `upstream_errors` 形成详情链；
- 详情接口不可用时降级成摘要链，并明确提示可能缺少中间尝试；
- 对更高优先级账号检查平台、分组、到期状态、当前健康、总/日/周配额和容量；
- 模型资格优先按 sub2 官方 `model_mapping` 语义判断，包括大小写、末尾 `*` 通配符和 Gemini 模型别名；
- 旧版账号响应未暴露模型映射时，可点击“核对保存模型”读取本机 sub2 数据，不会自动同步上游；
- 会话粘连、调度权重和未持久化的历史候选评分仍标为未知，不做过度推断。

### 请求历史与路由回放

- 展示最近 30 分钟内最多 30 条真实成功和失败请求；
- 展示请求时间、模型、分组、最终账号、状态、总耗时和可用的真实首字耗时；
- 可按模型、分组、最终账号和直接成功 / 故障转移 / 最终失败筛选；
- 只有点击某条历史记录时，才按请求 ID 读取其关联上游错误和最多 8 条详情；
- 详情缺失时继续保持“部分详情 / 摘要 / 信息不足”证据边界；
- 请求回放只读取本机 Ops 日志，不会重发请求或访问模型上游；
- 账号 TTFT 汇总读取最新最多 1000 条流式记录，展示滚动 24 小时 P90、P50、最新样本、样本数和分页覆盖状态；
- 缺失 `first_token_ms` 时不会用总耗时补值，也不会根据 TTFT 自动摘出、挂回或调整账号。

### 事件中心与可靠性统计

- 记录请求级或上游尝试级的 429、403 和 5xx 真实错误；
- 对比连续账号快照，记录进入冷却、冷却更新、冷却结束和同一完整路由范围内的最近命中账号变化；
- 命中变化要求分组 ID、平台和请求模型完全一致；其它分组或模型的交错请求不会参与比较；
- 打开事件中心后按需读取近 24 小时请求，不把 24 小时统计加入每 10 秒主刷新；
- 展示成功率、最终失败数、已识别故障转移成功次数和受关注状态码数量；
- 请求或错误分页未覆盖完整时，将故障转移数标为下限并说明样本边界；
- 本地事件默认保留 7 天，可切换为 24 小时或 30 天；
- 每次合并事件都会去重、删除过期记录并只保留最新 500 条，也可手动清空；
- 本地事件不会上传到 GitHub、sub2api 或任何第三方服务。

### 账号路由管理

- 紫色 `P数字` 标签突出账号优先级；
- 手动提升或降低账号优先级；
- 摘出或挂回调度池；
- 清除限流、过载或临时熔断冷却；
- 只读展示池模式，不提供容易误用的快捷切换；
- 显示组内优先级和账号所属分组。

### 一键添加 API Key 账号

- 顶部 `+` 按钮打开添加账号窗口，第一版只支持 OpenAI / GPT 与 Anthropic / Claude 的 `apikey` 账号；
- 地址只接受 HTTPS，或本机 `localhost`、`127.0.0.1`、`[::1]` 的 HTTP；拒绝 URL 凭据、查询参数、片段和其它协议；
- 一次识别会通过当前 sub2 的同源预览接口分别尝试两种协议，必须恰好有一种返回允许的同族模型；
- 目标分组只依据真实 `group.platform`：当前兼容分组优先、唯一兼容分组自动选择、多个分组要求手选、没有兼容分组时禁止创建；
- 确认页显示生成名称、平台、模型数、并发 `1` 和账号级优先级；创建后以后端回读的组内优先级为准；
- 创建请求带一次性幂等键；提交期间禁止重复点击、关闭或最小化，结果不确定时可用同一幂等键重试。

### 人工容量调节

- 每个账号提供独立“容量”编辑器，显示配置容量、当前占用和排队；
- `-` / `+` 只调整输入值，必须点击“应用”才写入；
- 只允许 `1` 到 `10000` 的正整数，避免误设成无限制容量；
- 新容量低于当前占用时明确提示：已有请求不会中断，新请求可能暂时排队；
- 更新只向官方账号接口提交 `{ concurrency }`，不会连带修改分组、凭据、优先级、`load_factor` 或池模式；
- 保存失败时保留编辑器和原输入，成功后重新读取账号及 Ops 容量快照；
- 不提供自动扩缩容或批量容量修改。

### 日配额

API Key / Bedrock 账号支持：

- 查看当日已用金额和每日美元限额；
- 使用率达到 80% 或 100% 时显示警告色；
- 手动设置或取消每日限额；
- 保存前读取账号最新详情，完整保留其它 `extra` 字段；
- 取消限制时只清理日配额相关字段。

### 余额与消费风险

- 账号余额来源必须逐个配置，支持明确协议的 `sub2api` 与 `newapi`；
- `newapi` 使用独立的 Access Token 和 User ID，不复用配在 sub2 中的 API Key；
- 账号卡片始终展示 sub2 的今日请求数、今日花费和单均费用；
- 余额查询成功后，USD 余额可结合今日截至当前的平均花费速率粗略估算剩余小时；
- 续航是基于今日历史速率的估算，不代表实时上游倍率，也不是消费承诺；
- 今日统计不可用或窗口不足时明确显示信息不足，不把缓存值冒充当前事实；
- 查询结果只保留在当前页面内存中，刷新页面后需再次手动查询；
- 余额配置可逐账号清除，清除操作需要用户确认。

### 模型与上游链接

- 查看 sub2 已保存的账号模型并搜索；
- 只有明确点击后才拉取上游模型，缺失、冲突或不支持的真实分组平台会在请求前阻止同步；
- OpenAI 分组只保留 GPT / ChatGPT / o 系列 / Codex 文本模型，Anthropic 分组只保留 Claude 模型；
- 同步会新增当前允许的同名映射、删除过期或错族的系统同名映射，并保留手工别名；有删除时必须再次确认；
- 持久化只通过单账号 `bulk-update` 合并完整 `model_mapping`，不重建或覆盖其它凭据字段；
- 账号名称可打开 `base_url` 对应的站点根地址；
- 只有名称文字和外链图标可以点击，标题栏空白处不会误触；
- 链接只允许 HTTP / HTTPS，并使用 `noopener noreferrer`。

### 布局与刷新

- 约 430px 宽的竖向单列面板；
- 桌面端高度约为视口的 88%，最高 1000px，并受视口剩余空间限制；
- 账号列表内部滚动并保持滚动位置；
- 面板可见且标签页位于前台时，每 10 秒刷新本机详情；
- 最小化、后台标签、添加账号窗口或账号容量 / 日配额 / 余额编辑与余额查询期间暂停刷新；
- 近 24 小时可靠性只在事件中心打开时按需读取，且一分钟内复用缓存；
- 运维日志读取有超时保护，不会阻塞账号列表主刷新。

## API 边界

主要只读接口：

```text
GET  /api/v1/admin/accounts
GET  /api/v1/admin/accounts/:id
GET  /api/v1/admin/groups/all
POST /api/v1/admin/accounts/today-stats/batch
GET  /api/v1/admin/ops/requests
GET  /api/v1/admin/ops/upstream-errors
GET  /api/v1/admin/ops/upstream-errors/:id
GET  /api/v1/admin/ops/concurrency
GET  /api/v1/admin/usage
GET  /api/v1/admin/accounts/:id/models
```

只有用户明确点击时才调用上游模型读取接口；这两个 POST 本身不持久化账号配置：

```text
POST /api/v1/admin/accounts/models/sync-upstream-preview
POST /api/v1/admin/accounts/:id/models/sync-upstream
```

只有用户确认操作时才调用写接口：

```text
POST /api/v1/admin/accounts
POST /api/v1/admin/accounts/bulk-update
POST /api/v1/admin/accounts/:id/schedulable
POST /api/v1/admin/accounts/:id/recover-state
PUT  /api/v1/admin/accounts/:id
```

OpenAI API Key 账号创建后，sub2 官方创建端点可能异步执行 Responses 能力探测；这是后端既有副作用，不是脚本调用 test / probe 接口。

只有用户真实点击余额按钮时才访问外部接口：

```text
GET <allowlisted-https-origin>/v1/usage
GET <allowlisted-https-origin>/api/user/self
```

## 安全边界

- 复用当前 sub2 后台的 `localStorage.auth_token`，不会在仓库中保存管理员凭据；
- 不读取 sub2 现有账号 `credentials` 中的 API Key 明文；余额凭据和新账号密钥必须由用户在脚本面板中另行输入；
- 余额凭据以未加密形式按“当前 sub2 地址 + 账号 ID”存入 Tampermonkey 的脚本存储，不写入网页 `localStorage`、sub2、日志、诊断信息或 GitHub；
- 已保存的余额密钥不会回填到页面 DOM；新输入凭据只属于输入时的来源类型和规范化域名，改变目的地后必须重新输入；
- 新账号 API Key 不写入 Tampermonkey、`localStorage`、日志、诊断、剪贴板、页面结果或仓库文件，只进入当次同源预览 / 创建请求，并在完成、取消或终止失败后清除；
- 账号创建不从浏览器直连候选上游，必须由当前 sub2 后台预览；没有唯一平台和一个兼容启用分组时不创建；
- 模型同步只提交完整 `model_mapping` 合并值，不发送从详情响应中取得的脱敏凭据快照；
- 外部请求只允许脚本元数据中声明的 HTTPS 域名、标准端口和固定路径，并拒绝重定向；
- 外部请求不携带第三方 Cookie，且必须来自余额按钮的真实用户点击；
- 不主动测活、不自动同步模型；
- TTFT 仅作只读证据，不自动调整调度、优先级、容量、池模式、配额或账号状态；
- 不提供伪通用余额查询：只实现本文明确列出的 `sub2api` 与 `newapi` 两种协议；
- 不修改 sub2api 源码、镜像、容器或数据库结构。
